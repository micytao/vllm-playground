# vLLM Playground v0.1.9 - CI/CD Pipeline, Configurable Container Images & Remote Fixes

**Release Date:** September 2026

This release ships a full **CI/CD pipeline** (automated tests + GitHub Actions on every PR, plus a gated PyPI release process), a new **Settings tab for configurable container image versions**, and fixes real chat-error handling and MaaS gateway support in **Remote mode**.

---

## Highlights

### CI/CD Pipeline

Every pull request now runs a layered test suite automatically: lint/format, unit tests (Python 3.9/3.11/3.12), FastAPI API tests, container-manager tests against a real Podman daemon, Kubernetes-manager tests against a real `kind` cluster, and Playwright frontend smoke tests — all in about two minutes.

- Real CPU tiny-model end-to-end chat test, and Podman/OpenShift container image builds, now run automatically as a **required gate right before every release** (not on every PR), so a broken release can't ship.
- Releases are tag-triggered (`vX.Y.Z`), version/changelog-verified, and published to PyPI via **Trusted Publishing (OIDC)** — no stored API token.
- While building this pipeline, the new container-build checks caught (and this release fixes) two pre-existing bugs: both the Podman and OpenShift container images failed to start with `ModuleNotFoundError: No module named 'vllm_playground'`, because `app.py` was being run as a bare script instead of as part of the installed package. Both Containerfiles are fixed and verified to boot and respond on `/api/status`.

### Configurable Container Image Versions

New **Settings** tab lets you pick vLLM/vLLM-Omni container image versions per accelerator from a dropdown (sourced live from Docker Hub, cached, with an offline fallback list) instead of relying on hardcoded tags.

- Per-accelerator overrides persist and default back to the built-in version when unset; picking the default-tagged option resets it.
- Version bumps: `vllm/vllm-openai` and `vllm/vllm-openai-rocm` → v0.29.0, `vllm/vllm-omni` and `vllm/vllm-omni-rocm` → v0.28.0.
- CPU mode now uses the official multi-arch `vllm/vllm-openai-cpu:v0.29.0` image (covers macOS ARM64 + Linux x86_64) instead of a self-built Quay image.
- AMD GPU default switched from `rocm/vllm:latest` to the versioned `vllm/vllm-openai-rocm` so the AMD dropdown has real tags to offer.

### Remote Mode Fixes

- Fixed silent **"No response from model"** failures during streaming chat in Remote mode: upstream error responses were being serialized as invalid JSON (Python dict `repr`, not `json.dumps`), which the frontend's `JSON.parse` silently dropped. Errors now surface as real, readable messages.
- Added generic support for **MaaS/KServe-style gateways** that advertise a dedicated base URL per model (via `GET /v1/models`) instead of one shared OpenAI-compatible root — Remote mode now detects and uses per-model URLs automatically, with a self-healing retry if the shared root 404s.
- Fixed a token-count fallback bug that fabricated "1 out" tokens on failed requests, and distinguished a genuinely empty-but-successful response (e.g. an embedding-only model selected for chat) from a real failure.

### Recipes Catalog

- Synced the recipes catalog with the latest upstream vLLM recipes (as of 2026-07-02), including the new `ArceeAI/Trinity-Large-Thinking` recipe.

## Upgrade Notes

- If you run the OpenShift or Podman container images built from this repo's `Containerfile`s, upgrade to this release — prior images failed to start at all.
- No settings migration needed; existing container image tags keep working unless you explicitly pick an override in the new Settings tab.
